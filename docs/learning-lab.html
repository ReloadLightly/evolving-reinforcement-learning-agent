01 · Learning a value estimate

What should the critic predict?

A critic estimates future discounted reward for an observation and action. TD3 trains two critics toward a target that combines the reward just observed with the smaller of two target-critic estimates for the next step.

y = r + γ × (1 − terminated) × min(Q₁′, Q₂′)

The episode continues, so the target includes an estimate of future reward. This use of another estimate is called bootstrapping.

The smaller estimate is Q₁′ = −5.00. With negative values, “smaller” means more negative.

Try it: set γ to zero, then switch to true termination. Both remove the future-value term for different reasons. Now choose a time limit: our learner still bootstraps from the final observation before the environment resets.

The primes denote slowly updated target networks. In the actual algorithm, both target critics evaluate the same next action from the target actor, with clipped Gaussian smoothing noise. Each live critic minimizes squared error to y; the live actor is trained through the first live critic every second critic update. Taking the minimum helps counter overestimation; it does not reveal the true value or guarantee an accurate target. Here Q₁′ and Q₂′ are illustrative inputs.

02 · Choosing what to learn from

Same stored experience. Different minibatch.

An ERL generation collects four population episodes and one learner episode. With equal episode lengths, 80% of new transitions come from the evolutionary population. The replay intervention changes the source mixture sampled for learning.

50.0%

Each step changes one of the 128 sampled transitions. Sampling is with replacement, so cells can represent repeated visits to the same stored transition.

Cells are grouped by source for readability. The implementation shuffles balanced minibatches before training.

A balanced batch contains exactly 64 EA samples and 64 learner samples.

Pooled replay is different: if 80% of resident transitions are EA, a uniformly sampled batch has 102.4 EA samples in expectation and 25.6 learner samples. Every real batch has integer counts that fluctuate.

At an 80:20 resident mix, this quota gives each learner transition 4.00× the expected sampling frequency of each EA transition.

What stays fixed: one global FIFO buffer, its capacity, and its eviction rule. Inserting a new transition into a full buffer removes the globally oldest transition regardless of source. A 50:50 sampled batch does not imply 50:50 storage.

The relative per-transition sampling rate is [(1 − α) / 0.2] ÷ [α / 0.8], assuming an 80:20 resident mix. It describes expected reuse pressure, not learning quality. Real source counts and ages are logged separately. Only the 50:50 quota is the primary balanced treatment; the other slider positions are teaching examples, not additional executed experimental arms.

03 · Counting the cost honestly

Interactions are not gradient updates.

The first 10,000 training transitions fill replay with random actions. Afterwards, the protocol grants one twin-critic update per four newly collected transitions. Every second twin-critic update also trains the actor.

1,280,000 replay samples are drawn at minibatch size 128. These are repeated uses of stored data, not additional simulator transitions.

Under the pilot evaluation schedule (every 10,000 training steps, including step zero), 6 checkpoints × 5 episodes × 200 steps add 6,000 evaluation transitions: 56,000 simulator transitions in total.

Try it: return to the warmup boundary. The buffer has experience, but the learner has made zero gradient updates. Then increase the budget: replay can be sampled many more times than the environment is stepped.

The calculation applies to the declared fixed-length Pendulum schedule, with evaluation at completed 10,000-step checkpoints. Evolutionary fitness episodes already count as training interactions. Reacher has shorter episodes and uses fractional update credits across generations; the same cumulative formula still applies. Equal transition and update budgets control two costs, but wall time, simulator cost, memory, and checkpoint writes must still be measured.
